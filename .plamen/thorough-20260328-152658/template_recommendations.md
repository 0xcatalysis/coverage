## Recommended Templates with Instantiation Parameters

### 1. SEMI_TRUSTED_ROLES (REQUIRED)
- **Trigger**: 7+ semi-trusted roles detected (QUOTE_SIGNER_ROLE, CREATOR_ROLE, SWAP_MANAGER_ROLE, SWAP_EXECUTOR_ROLE, PREMIUM_COLLECTOR_ROLE, CoveredVaultWrapper owner, CoverPool curator)
- **Parameters**:
  - Roles: QUOTE_SIGNER_ROLE (sign quotes), CREATOR_ROLE (deploy pools, set implementations), SWAP_MANAGER_ROLE (configure routes), SWAP_EXECUTOR_ROLE (execute swaps), PREMIUM_COLLECTOR_ROLE (distribute premiums)
  - Owner roles: CoveredVaultWrapper owner (timelocked params, gate, upgrade), CoverPool curator via DEFAULT_ADMIN_ROLE (bind policies, approve claims, set fees)
  - Key concern: SWAP_MANAGER_ROLE can configure malicious swap routes; CREATOR_ROLE can change implementation; CoveredVaultWrapper owner has 2h timelock for premium rate (short window for user exit)

### 2. TOKEN_FLOW_TRACING (REQUIRED)
- **Trigger**: BALANCE_DEPENDENT flag — multiple balance-diff patterns
- **Parameters**:
  - Balance-diff sites: CoveredVaultWrapper._claimInsurance (balance before/after fileClaim), Swapper._performSwap (balance before/after DEX call)
  - Token flow: underlying asset → Morpho vault → CoveredVaultWrapper → ClaimManager → beneficiary
  - Premium flow: vault shares (PremiumCollector) → underlying → PremiumManager → splits (treasury, pool, restaker)
  - Collateral flow: SlashingManager → ClaimManager → Swapper → beneficiary

### 3. ZERO_STATE_RETURN (REQUIRED)
- **Trigger**: ERC4626 vault with first-depositor patterns
- **Parameters**:
  - Vault: CoveredVaultWrapper (ERC-4626 with 6-decimal offset protection)
  - First deposit concern: `_decimalsOffset() = 6` provides some protection. Deposits blocked until policyBound (depositCap=0 before onPolicyBound)
  - Zero-state paths: totalPrincipal=0 (no premium accrual), policyId=0 (no insurance claims)
  - Edge: What happens if all users withdraw (totalPrincipal→0) then new deposits arrive? cumulativePremiumPerUnit is already elevated — new user's `userPremiumDebt` must be correctly set to avoid immediate premium obligation

### 4. TEMPORAL_PARAMETER_STALENESS (REQUIRED)
- **Trigger**: TEMPORAL flag — extensive time-dependent logic
- **Parameters**:
  - Premium accrual: `_accruePremium()` called on every deposit/withdraw/collectPremium
  - Active window: `_activeElapsedFrom(checkpoint)` with policy start/maturity + gateGracePeriod
  - Timelocks: 2h/2d/7d delays for parameter changes
  - Stale premium: If no deposit/withdraw/collectPremium happens for a long time, premium accumulates unbounded (capped only by _liabilityHeadroom)
  - distributeInterval: Controls frequency of premium collection in PremiumCollector

### 5. ECONOMIC_DESIGN_AUDIT (REQUIRED)
- **Trigger**: MONETARY_PARAMETER flag — premiumRatePerSecond, fee splits, insurance model
- **Parameters**:
  - Premium model: `premiumRatePerSecond × totalPrincipal × elapsed / WAD` per accrual cycle
  - Insurance model: `maxCoverableLossBps` cap on covered loss, `deductibleBps` threshold before payout
  - Fee splits: platform (≤25%) + pool (≤20%) + restaker (remainder)
  - Deposit cap: `coverageLimit × 10000 / maxCoverableLossBps`
  - Critical economic question: Can premiumRatePerSecond drain value faster than Morpho yield, causing a death spiral where withdrawals trigger insurance claims that drain coverage?

### 6. EXTERNAL_PRECONDITION_AUDIT (REQUIRED)
- **Trigger**: Multiple external interactions (Morpho, ChainlinkPriceFeed, StakeManager, SlashingManager, RewardsManager, Swapper/DEX)
- **Parameters**:
  - Morpho V2 dependency: convertToAssets() revert → fallback to lastKnownMorphoValue; redeem() revert → MorphoRedeemReverted
  - Chainlink dependency: getUSDValue in bindPolicy — no staleness check visible in scope
  - SlashingManager: previewSlashing + executeSlashing — returns collateral tokens/amounts
  - Swapper/DEX: quoteSwap may return 0 on failure (graceful); executeSwap requires amountOutMin

### 7. ORACLE_ANALYSIS (REQUIRED)
- **Trigger**: ORACLE flag — ChainlinkPriceFeed used in PolicyManager
- **Parameters**:
  - Oracle: IChainlinkPriceFeed.getUSDValue(token, amount) in PolicyManager.bindPolicy
  - Usage: Compares totalStakeUSD vs coverageLimitUSD to ensure sufficient backing
  - Risk: Stale/manipulated price could allow undercollateralized policies to be bound
  - Out-of-scope: IChainlinkPriceFeed implementation — but interface calls are in scope

### 8. SHARE_ALLOCATION_FAIRNESS (REQUIRED)
- **Trigger**: SHARE_ALLOCATION flag — proportional share tracking
- **Parameters**:
  - CoveredVaultWrapper: userPrincipal tracks cost basis per user; userMorphoShares tracks underlying vault shares per user
  - Premium allocation: reward-per-token accumulator pattern (cumulativePremiumPerUnit + userPremiumDebt)
  - Rounding: mulDiv with Floor rounding throughout; rounding dust accumulates in userMorphoShares (handled with final-withdrawal cap)
  - Fee splits: PremiumManager.getFeeSplits uses integer BPS division — rounding favors restaker (remainder)
